# Debian URL Parser - upstream_version 清理逻辑优化

## 修改时间
2025年12月20日

## 问题描述

之前的 `_clean_upstream_version` 方法会移除**所有** `+` 号后面的内容，导致 OpenJDK 等包的构建号（如 `+8`, `+7`）被错误移除。

### 问题案例
```
URL: openjdk-11-dbg_11.0.24+8-2~deb11u1_amd64.deb
期望 upstream_version: 11.0.24+8
旧逻辑返回: 11.0.24  ❌ (错误地移除了构建号)
```

## 解决方案

实现了**智能清理逻辑**，能够区分不同类型的 `+` 后缀：

### 保留规则
1. ✅ **保留** `+数字` 格式（如 `+8`, `+7`）- OpenJDK 等包的构建号
2. ✅ **保留**第一个 `~` 及其后的内容（预发布标识，如 `~rc1`, `~beta1`）

### 移除规则
1. ❌ **移除** `+dfsg` 及其变体（DFSG 重打包标识）
2. ❌ **移除** `+really...` （降级版本标识）
3. ❌ **移除** `+git...` （Git 快照标识）
4. ❌ **移除** `+svn`, `+cvs`, `+hg`, `+bzr` 等版本控制系统标识
5. ❌ **移除** `+ds` （Debian source 标记）
6. ❌ **移除** `+repack` （重新打包标记）
7. ❌ **移除**第二个 `~` 及其后的内容
8. ❌ **移除**所有 `-` 号后面的内容

## 实现细节

### 核心逻辑
```python
def _clean_upstream_version(self, upstream: str) -> str:
    # 1. 移除第二个 ~ 及其后的内容
    clean_version = re.sub(r'(~[^~+-]*?)~.*$', r'\1', clean_version)

    # 2. 移除已知的特殊标识
    clean_version = re.sub(r'\+really[\d.]+', '', clean_version)
    clean_version = re.sub(r'\+dfsg\d*', '', clean_version)
    clean_version = re.sub(r'\+git\d+', '', clean_version)
    # ... 更多特殊标识 ...

    # 3. 智能处理剩余的 + 后缀
    if re.search(r'\+\d+$', clean_version):
        # 保留 +数字 格式（构建号）
        pass
    else:
        # 移除其他所有 + 后缀
        clean_version = re.sub(r'\+.*$', '', clean_version)

    # 4. 移除所有 - 号后面的内容
    clean_version = re.sub(r'-.*$', '', clean_version)

    return clean_version
```

### 关键改进
1. **按类型识别**：先移除已知的特殊标识，再处理剩余的 `+` 后缀
2. **保留构建号**：使用 `\+\d+$` 模式识别并保留纯数字构建号
3. **顺序处理**：避免不同正则表达式之间的相互干扰

## 向后兼容性

### ⚠️ 破坏性变更
对于包含构建号的包（如 OpenJDK），`upstream_version` 的值会发生变化：

- **旧行为**: `11.0.24+8-1` → `upstream_version = "11.0.24"`
- **新行为**: `11.0.24+8-1` → `upstream_version = "11.0.24+8"`

### 影响范围
主要影响 **OpenJDK** 系列包，这些包使用 `主版本.次版本+构建号` 的格式。

其他类型的包（如普通的 DFSG、Really 等）不受影响。

## 建议

如果您的代码依赖于旧的 `upstream_version` 值（不含构建号），建议：

1. 更新代码以适应新的行为
2. 或者，如果需要不含构建号的版本，可以自行解析 `version` 字段
